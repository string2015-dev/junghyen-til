# 261104 멀티모달 RAG — 데이터 추출 & 분할 정리

> PDF 한 편을 **텍스트 / 표 / 이미지** 로 분리하는 것이 멀티모달 RAG의 출발점.
> → **파싱(Unstructured) → 요소 분류 → 텍스트 분할 → 저장** 까지 진행. (요약·임베딩·답변 생성은 다음 단계)

---

## 📌 오늘의 키워드

| 키워드 | 한 줄 설명 |
|---|---|
| **멀티모달 RAG** | 텍스트뿐 아니라 이미지·표도 검색 대상 + 답변 근거로 쓰는 RAG |
| **VLM** (Vision Language Model) | 이미지를 이해하는 모델. 멀티모달 RAG에는 LLM + VLM 필요 |
| **Unstructured Parser** | 제각각인 문서를 AI가 먹기 좋은 **표준 조각(Element)** 으로 분해하는 전처리 라이브러리 |
| **Element(요소)** | 파서의 출력 단위. Title / NarrativeText / Table / Image / Header·Footer 등 |
| **Metadata(메타데이터)** | 좌표, 파일명, 페이지 번호, 카테고리, element_id … → **출처 표기**의 근거 |
| **Partition Strategy** | `fast`(규칙 기반, 빠름) / `hi_res`(모델 기반, 정확) / `ocr_only`(스캔본) / `auto` |
| **트레이드오프** | 속도 ↔ 품질. 문서 종류(도메인)를 이해하고 전략 선택 |
| **by_title 청킹** | 제목(Title)을 만나면 새 청크 시작 → 의미 단위 보존 |
| **CompositeElement** | by_title 청킹 후 만들어지는 **텍스트 덩어리** 타입 |
| **Chunk size / overlap** | 청크 최대 크기 / 앞뒤로 겹치는 크기 (문맥 끊김 방지) |
| **Multi-Vector 구조** | 검색은 **요약**으로, 답변은 **원본**으로 (다음 단계에서 구현) |
| **Poppler / Tesseract** | OS에 직접 설치하는 도구. 각각 PDF→이미지 변환 / 이미지 속 글자 읽기(OCR) |
| **가상환경(.venv)** | 프로젝트별 독립 파이썬 환경. 활성화 후 설치해야 함 |
| **절대경로 / 상대경로** | 절대 = 드라이브(root) 기준, 상대 = 현재 위치 기준 |
| **pickle** | 파이썬 객체를 파일로 저장 → 다음 실습에서 그대로 불러옴 |

## 1. 멀티모달 RAG란?

| 구분 | 일반 RAG | 멀티모달 RAG |
|---|---|---|
| 검색 대상 | 텍스트만 | 텍스트 + 이미지 + 표 |
| 버려지는 데이터 | 그래프, 사진, 표 구조 | 없음 |
| 답변 근거 | 텍스트 청크 | 텍스트 청크 + 원본 이미지 + 원본 표 |
| 필요한 모델 | LLM | LLM + VLM |

- 비유: 일반 RAG = **글자만 읽는 사서** / 멀티모달 RAG = **그림과 표도 볼 줄 아는 눈을 단 사서**

## 2. 전체 파이프라인 & 아키텍처

```
PDF ─▶ Unstructured Parser ─┬▶ 텍스트 ─┐
                            ├▶ 표     ─┼▶ 각각 요약 ─▶ 요약을 임베딩해 저장
                            └▶ 이미지 ─┘              (원본은 요약에 붙여 보관)
질문 ─▶ 요약으로 검색 ─▶ 원본(텍스트·표·이미지) 꺼냄 ─▶ 멀티모달 LLM ─▶ 답변
```

1. **문서 데이터 파싱** — 텍스트·표·이미지 분리 (오늘 한 부분)
2. **데이터 저장 및 검색** — 요약본을 인덱싱, 검색되면 원본을 반환 (도서관 **색인 카드** → 서가에서 **진짜 책** 꺼내기)
3. **답변 생성** — 멀티모달 LLM이 요약 + **원본**을 함께 사용

**필수 질문 2가지**
- Q. 왜 이미지를 굳이 요약? → 이미지는 그 자체로 검색 불가. **텍스트 요약으로 바꿔야** 임베딩·검색됨
- Q. 요약만 LLM에 주면 안 되나? → 요약은 디테일이 날아감. **검색엔 요약, 답변엔 원본**

## 3. Unstructured Parser 톺아보기

- 출력 = 문자열이 아니라 **Element 객체의 리스트** (텍스트 + 의미 구조 + 메타데이터)
- RAG 품질을 가장 크게 좌우하는 건 **① 파싱 단계** → *Garbage In, Garbage Out*
- 문서 처리는 **어떤 문서인지 이해(도메인 이해)** 가 먼저

```
원본 문서 → ①Parser → Element 리스트 → ②Chunking → ③Embedding → ④Vector DB → ⑤검색·LLM 답변
```

**주요 Element 카테고리**

| 카테고리 | 의미 | 활용 |
|---|---|---|
| Title | 제목/소제목 | **청킹 기준** |
| NarrativeText | 서술형 본문 | 검색의 주요 재료 |
| Table | 표 | HTML로 구조 보존 가능 |
| Image | 이미지 블록 | 멀티모달 확장 |
| Header / Footer | 머리글·꼬리글 | 보통 제거(노이즈) |
| UncategorizedText | 분류 실패 텍스트 | **품질 점검 지표** (많으면 파싱 실패) |

**Metadata** — 좌표, 파일 경로, 언어, 수정일시, **페이지 번호**, 카테고리, element_id
→ 답변에 "출처: 사업계획서.pdf 12페이지" 처럼 **근거 표기** 가능 (포트폴리오 차별화 포인트)

**Partition Strategy (⭐ 가장 중요)**

| 전략 | 방식 | 속도 | 정확도 | 언제 |
|---|---|---|---|---|
| `auto` | 자동 선택 | 가변 | 가변 | 처음 테스트 |
| `fast` | 텍스트 레이어만 빠르게 추출 | ⚡⚡⚡ | ★★ | 깨끗한 텍스트 PDF |
| `hi_res` | **레이아웃 모델**로 요소 인식 | 🐢 | ★★★★★ | 표·다단·복잡한 문서 |
| `ocr_only` | OCR로만 추출 | 🐢🐢 | ★★★ | 스캔본·사진 |

- `fast` = 복사-붙여넣기(빠르지만 "이게 표인지" 모름) / `hi_res` = 사람이 눈으로 보고 판단(느리지만 표가 안 깨짐)

**처리 4단계**: Partition(요소 분해) → Cleaning(노이즈 제거) → Chunking(재조립) → Staging(다른 포맷 변환)

**`by_title` 이 특별한 이유**
- 일반 글자 수 분할 = 100페이지마다 칼로 자르기 → 문장·표 중간이 잘림
- `by_title` = **챕터 제목이 나올 때마다 새 묶음** → 의미 보존

**한국어 팁**: `languages=["kor","eng"]` 명시 + `tesseract-ocr-kor` 설치 / HWP는 직접 지원 안 함 → PDF 변환 후 투입 / 국내 공문서는 Upstage Document Parse 등과 **비교 테스트 후 근거 있게 선택**

## 6. 생각해 볼 질문 정리

- **`hi_res`를 빼면 왜 표·이미지가 안 잡힐까?** → `fast`는 텍스트 레이어만 읽는 규칙 기반이라 레이아웃(표 영역·그림 영역)을 인식하지 못함
- **왜 겹치게(overlap) 자를까?** → 경계에서 문장·문맥이 끊기면 의미가 사라지고 검색 품질이 떨어짐
- **이미지가 파일로만 있으면 왜 검색이 안 될까?** → 이미지는 텍스트가 아니라 임베딩·의미 검색 불가 → **VLM으로 텍스트 요약 → 임베딩 → 벡터 검색** 필요 (다음 단계)

## 7. 자주 나는 에러

| 증상 | 원인 | 해결 |
|---|---|---|
| `PDFInfoNotInstalledError` | Poppler 미설치/Path 누락 | 설치 후 **재시작** |
| `TesseractNotFoundError` | Tesseract Path 누락 | Path 추가 후 재시작 |
| `FileNotFoundError` | PDF 경로·파일명 오류 | `fname`, `존재 여부` 확인 |
| `figures/` 비어 있음 | `hi_res`·`extract_images_in_pdf` 누락 | 옵션 확인 |
| `NameError: texts` | 앞 셀 미실행 | 위에서부터 순서대로 재실행 |
| 파싱이 안 끝남 | 정상 (`hi_res`는 느림) | 2~3분 대기 |

## 9. 전체 흐름 코드 (한눈에 보기)

```python
# =====================================================================
# 멀티모달 RAG ① 데이터 추출 & 분할 전체 흐름
#   PDF ─▶ Unstructured(hi_res) ─▶ 텍스트/표/이미지 분리
#       ─▶ 텍스트 재분할(토큰 기준) ─▶ pickle 저장
# =====================================================================
import os, time, pickle
from pathlib import Path
from collections import Counter
from langchain_text_splitters import CharacterTextSplitter    # 텍스트 자르는 '작두'
from unstructured.partition.pdf import partition_pdf          # PDF 자동 분리수거 기계

# ---------------------------------------------------------------------
# [1] 경로 설정 ─ 한글·공백 없는 경로 사용 (unstructured 오류 방지)
# ---------------------------------------------------------------------
PROJECT_ROOT = Path.cwd().parent if Path.cwd().name == "practice" else Path.cwd()
fname = "invest.pdf"                                    # 처리할 PDF 파일명
fpath = str(PROJECT_ROOT / "data") + os.sep             # PDF가 있는 폴더 (끝에 구분자 포함)
assert os.path.exists(fpath + fname), "PDF 경로를 확인하세요"   # 없으면 이후 단계 전부 실패

# ---------------------------------------------------------------------
# [2] 추출 함수 ─ PDF → Element 리스트
# ---------------------------------------------------------------------
def extract_pdf_elements(path, fname):
    return partition_pdf(
        filename=path + fname,
        strategy="hi_res",                 # 레이아웃 모델 기반 정밀 추출 (느리지만 표·이미지 정확)
        extract_images_in_pdf=True,        # 그림을 figures/ 에 jpg로 저장
        infer_table_structure=True,        # 표의 행·열 구조까지 추론
        chunking_strategy="by_title",      # 제목 기준으로 의미 단위 묶기
        max_characters=4000,               # 블록 하드 상한
        new_after_n_chars=3800,            # 이 길이를 넘으면 새 블록 시작
        combine_text_under_n_chars=2000,   # 짧은 조각은 앞뒤와 결합
        extract_image_block_output_dir=path + "/figures",
    )

# ---------------------------------------------------------------------
# [3] 요소 분류 ─ 텍스트 / 표로 나누기
# ---------------------------------------------------------------------
def categorize_elements(raw_pdf_elements):
    tables, texts = [], []
    for element in raw_pdf_elements:
        t = str(type(element))
        if "unstructured.documents.elements.Table" in t:
            tables.append(str(element))                  # 표 → tables
        elif "unstructured.documents.elements.CompositeElement" in t:
            texts.append(str(element))                   # 텍스트 덩어리 → texts
    return texts, tables

# ---------------------------------------------------------------------
# [4] 추출 실행 (hi_res는 2~3분 소요) + 분류
# ---------------------------------------------------------------------
start = time.time()
raw_pdf_elements = extract_pdf_elements(fpath, fname)
```
