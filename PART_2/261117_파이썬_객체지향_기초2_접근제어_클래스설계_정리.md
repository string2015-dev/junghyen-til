## 1. 복습: 프로그래밍 언어와 객체지향

- **프로그래밍 언어**는 사람과 컴퓨터의 의사소통 수단입니다.
- 컴퓨터는 **기계어**(0과 1)만 이해하므로, **컴파일러**가 사람이 쓴 코드를 기계어로 번역합니다.
- **객체지향 언어**는 객체를 먼저 생각하고 프로그래밍합니다.
  - class를 기반으로 object(instance)를 만듭니다.
  - class는 **속성(attribute)** 과 **동작(method)** 을 가집니다.

```python
class Student:
    def __init__(self, name, grade):   # 생성자
        self.name = name               # 속성 (데이터)
        self.grade = grade
    def study(self):                   # 메서드 (동작)
        print(self.name, '이 공부합니다.')

s = Student("Yumi", 3)   # class → object(instance)
s.study()
```

> (참고) 리눅스를 공부할 때는 리눅스 매뉴얼(`man`)을 보는 습관을 들이자.

## 2. 객체지향과 표준 모델링

- 객체지향을 하려면 먼저 **표준화된 모델링**이 필요합니다. 객체지향 프로그래밍은 일종의 **표준화된 규격**이라고 볼 수 있습니다.
- 서비스 기획과도 연결됩니다.
  - 상품에 대한 **서베이(조사)** 가 되어 있어야 서비스의 신뢰가 올라갑니다.
  - 요즘은 사용자층이 너무 넓기 때문에 **타깃을 명확하게** 정하는 것이 중요합니다.

## 3. 설계 순서: 데이터 먼저, 기능은 그다음

프로젝트에서는 **데이터 엔티티 모델링**을 가장 먼저 진행합니다.

| 문서 | 역할 |
|---|---|
| **ERD** | 데이터의 명세서 |
| **기능명세서** | ERD의 데이터를 처리할 기능 정리 |

### 설계할 때 생각하는 순서

1. **어떤 데이터**를 가지고 객체로 만들 것인가? → 속성
2. **어떤 기능**으로 그 데이터를 처리할 것인가? → 메서드(함수)로 정의
3. 그 기능을 데이터를 다루는 **함수**로 넣을지, 밖에 보여 줄 **인터페이스**로 넣을지 정하기

### 추상화

- 필요한 요소만 사용해서 객체를 표현하는 것입니다.
- 예: 은행 계좌를 만들 때 "계좌 색깔"은 필요 없고, **소유자·잔액**과 **입금·출금**만 있으면 됩니다.

### Has-a 관계 (포함 관계)

- 한 class가 다른 객체를 속성으로 가지고 있는 관계입니다.

```python
class Customer:
    def __init__(self, name, account):
        self.name = name
        self.account = account   # Customer has-a BankAccount
```

## 4. 접근 제어 (public / protected / private)

- **액세스 모디파이어(Access Modifier)**: 모든 언어에 접근 제어가 있고, 이것으로 데이터를 안전하게 유지·관리합니다.
- 접근 제어가 없으면 밖에서 `acc.balance = -50000`처럼 데이터를 마음대로 망가뜨릴 수 있습니다.

| 표기 | 이름 | 의미 | 밖에서 접근 | 비유 |
|---|---|---|---|---|
| `name` | public | 누구나 사용 | ✅ 됨 | 진열대 |
| `_name` | protected | 내부·자식 클래스용 (약속) | ⚠️ 되지만 하면 안 됨 | 창고 (Staff Only) |
| `__name` | private | 이 클래스 안에서만 | ❌ `AttributeError` | 금고 |

### 파이썬에는 완벽한 private이 없다

파이썬은 두 가지 방법으로 대신합니다.

1. **약속(convention)**: `_`가 붙으면 "건드리지 말자"는 신호
2. **이름 바꾸기(name mangling)**: `__balance` → `_BankAccount__balance`

```python
acc.__balance                # ❌ AttributeError
acc.__dict__                 # {'owner': '하늘', '_BankAccount__balance': 10000}
acc._BankAccount__balance    # 바뀐 이름을 알면 접근 가능 (실무에서는 금지)
```

### 주의할 점

- `__init__`처럼 **앞뒤로** 밑줄 2개 = 특별 메서드 (private 아님)
- 밖에서 `acc.__balance = 999`를 하면 원래 값이 바뀌지 않고 **새 속성이 추가**될 뿐입니다.

## 5. getter / setter / @property

- private으로 숨긴 값은 **메서드(창구)** 를 통해서만 읽고 씁니다.
- setter를 쓰면 값을 바꾸기 전에 **검사(validation)** 를 할 수 있습니다.
- `@property`를 붙이면 `acc.balance`처럼 괄호 없이 읽을 수 있고, setter가 없으면 **읽기 전용**이 됩니다.

```python
def deposit(self, amount):     # setter 역할
    if amount <= 0:
        print("잘못된 입금액입니다.")
        return
    self.__balance += amount

@property
def balance(self):             # getter를 속성처럼
    return self.__balance
```

## 6. VO와 DTO

| 이름 | 풀네임 | 역할 |
|---|---|---|
| **VO** | Value Object | **값 자체**를 표현하는 객체. 데이터만 처리하고, 보통 만든 뒤 값을 바꾸지 않음. 값이 같으면 같은 객체로 봄 |
| **DTO** | Data Transfer Object | 계층 사이(예: DB ↔ 화면)에서 **데이터를 전달**하기 위한 객체. 로직 없이 데이터만 담음 |

## 7. 전체 흐름 한눈에 보기

```python
# =====================================================================
# 오늘의 흐름
#  1) 추상화  : 은행 계좌에서 필요한 것만 고른다 → 소유자, 잔액 / 입금, 출금
#  2) 데이터 먼저(ERD) → 기능(기능명세서) 순서로 class 를 만든다
#  3) 접근 제어 : public / protected / private
#  4) getter / setter / @property 로 안전한 창구 만들기
#  5) Has-a : 고객이 계좌 객체를 "가진다"
#  6) VO / DTO : 값만 담는 객체, 데이터 전달용 객체
# =====================================================================


# ---------------------------------------------------------------------
# DTO (Data Transfer Object) : 데이터를 "전달"하기 위한 객체
#  - 로직 없이 데이터만 담는다
# ---------------------------------------------------------------------
class AccountDTO:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance


# ---------------------------------------------------------------------
# VO (Value Object) : "값" 자체를 표현하는 객체
#  - 값을 private 으로 숨기고 @property 로 읽기만 허용 → 바꿀 수 없음
#  - 값이 같으면 같은 것으로 본다 (__eq__)
# ---------------------------------------------------------------------
class MoneyVO:
    def __init__(self, amount):
        self.__amount = amount

    @property
    def amount(self):
        return self.__amount

    def __eq__(self, other):
        return self.amount == other.amount


# ---------------------------------------------------------------------
# BankAccount : 오늘의 핵심. 접근 제어 3종류를 모두 사용
# ---------------------------------------------------------------------
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner          # public    : 누구나 봐도 되는 정보
        self._bank = "AI은행"        # protected : 내부·자식 클래스용 (약속일 뿐, 막히진 않음)
        self.__balance = balance    # private   : 밖에서 직접 접근 불가 (이름이 바뀜)

    # getter : 읽기 창구
    def get_balance(self):
        return self.__balance

    # @property : 괄호 없이 acc.balance 로 읽기. setter 가 없으니 읽기 전용
    @property
    def balance(self):
        return self.__balance

    # setter 역할 : 값을 바꾸기 전에 반드시 "검사"
    def deposit(self, amount):
        if amount <= 0:
            print("잘못된 입금액입니다.")
            return                  # 검사 실패 → 값을 바꾸지 않고 종료
        self.__balance += amount
        print(f"{amount}원 입금 → 잔액 {self.__balance}원")

    def withdraw(self, amount):
        if amount > self.__balance:
            print("잔액이 부족합니다.")
            return
        self.__balance -= amount
        print(f"{amount}원 출금 → 잔액 {self.__balance}원")

    # 밖으로 데이터를 넘길 때는 DTO 에 담아서 전달
    def to_dto(self):
        return AccountDTO(self.owner, self.__balance)


# ---------------------------------------------------------------------
# Customer : Has-a 관계 (고객이 계좌 객체를 속성으로 가짐)
# ---------------------------------------------------------------------
class Customer:
    def __init__(self, name, account):
        self.name = name
        self.account = account      # BankAccount 객체를 통째로 가짐

    def show(self):
        # 객체.객체.속성 으로 타고 들어가서 읽기 (private 은 property 로)
        print(f"{self.name} 고객 | {self.account._bank} | 잔액 {self.account.balance}원")


# =====================================================================
# 실행
# =====================================================================
acc = BankAccount("하늘", 10000)
cus = Customer("하늘", acc)
cus.show()                          # 하늘 고객 | AI은행 | 잔액 10000원

# 1) public / protected : 둘 다 접근은 된다 (protected 는 약속 위반)
print(acc.owner)                    # 하늘
print(acc._bank)                    # AI은행

# 2) private : 원래 이름으로는 에러
try:
    print(acc.__balance)
except AttributeError as e:
    print("에러:", e)               # 'BankAccount' object has no attribute '__balance'

# 3) name mangling 확인 : 실제 이름은 _BankAccount__balance
print(acc.__dict__)                 # {'owner': '하늘', '_bank': 'AI은행', '_BankAccount__balance': 10000}
print(acc._BankAccount__balance)    # 10000 (가능하지만 실무 금지)

# 4) 자주 하는 실수 : 밖에서 __balance 에 대입 → 새 속성만 생김, 진짜 잔액은 그대로
acc.__balance = 99999999
print(acc.get_balance())            # 10000

# 5) setter 의 검사 기능
acc.deposit(-500)                   # 잘못된 입금액입니다.
acc.deposit(5000)                   # 5000원 입금 → 잔액 15000원
acc.withdraw(100000)                # 잔액이 부족합니다.
acc.withdraw(3000)                  # 3000원 출금 → 잔액 12000원

# 6) @property 는 읽기 전용
try:
    acc.balance = 0
except AttributeError as e:
    print("에러:", e)               # property 'balance' of 'BankAccount' object has no setter

# 7) VO : 값이 같으면 같은 것
print(MoneyVO(1000) == MoneyVO(1000))   # True

# 8) DTO : 데이터만 담아서 전달
dto = acc.to_dto()
print(dto.owner, dto.balance)       # 하늘 12000
```
